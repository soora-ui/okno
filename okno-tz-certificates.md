# ТЗ: Подарочные сертификаты — okno.business

## 1. Общее описание

Функционал позволяет мастеру создать собственный визуальный шаблон подарочного сертификата (на основе загруженного логотипа и выбранных цветов), после чего система генерирует сертификаты на разные суммы в едином стиле. Каждый сертификат снабжается уникальным QR-кодом для проверки подлинности при погашении.

**Формат сертификата:** A5, альбомная ориентация (landscape).
- Размер в мм: 210 × 148 мм
- Размер в пикселях при 300 DPI (для печати): 2480 × 1748 px
- Размер в пикселях при 150 DPI (для экрана/скачивания): 1240 × 874 px
- Соотношение сторон: 35:24 (~1.459:1)
- Формат вывода: PNG (для просмотра/скачивания) + PDF (для печати)

## 2. Пользовательские сценарии

### 2.1. Мастер настраивает шаблон (один раз)

1. В личном кабинете мастер заходит в раздел «Сертификаты» → «Настроить дизайн»
2. Загружает логотип (PNG/SVG/JPG, до 5 МБ, рекомендуемое разрешение — не менее 1000×1000 px)
3. Выбирает основную и дополнительную цвета (color picker), либо система предлагает автоматически извлечь палитру из логотипа
4. Опционально — вводит название студии, слоган/тэглайн, контакты (телефон, адрес), которые попадут в шаблон
5. Нажимает «Сгенерировать шаблон»
6. Система через Claude API генерирует HTML/SVG-шаблон формата A5 landscape с плейсхолдерами
7. Мастеру показывается превью на тестовой сумме (например, 1000 ₽)
8. Мастер может запросить перегенерацию (с теми же или скорректированными настройками) либо подтвердить и сохранить шаблон
9. Утверждённый шаблон сохраняется в БД как связка `master_id → template_html/svg_source`

**Важно:** генерация шаблона через Claude API происходит **только на этом шаге**, не при каждой выдаче сертификата.

**Лимит перегенераций:** не более **3 раз на аккаунт** мастера (суммарно, жёсткий потолок, не «3 раза в месяц»). Счётчик хранится в таблице настроек мастера. При достижении лимита кнопка «Перегенерировать» блокируется с пояснением. Ручное редактирование сгенерированного шаблона (текст/позиционирование вручную) не предусмотрено — только перегенерация через ИИ с новыми исходными данными в рамках оставшихся попыток.

### 2.2. Клиент покупает сертификат

1. Клиент выбирает номинал сертификата **из списка, заданного мастером заранее** (свободной суммы нет — только фиксированные номиналы)
2. Оплачивает
3. Система создаёт запись в БД, генерирует уникальный токен, рендерит финальный PDF на основе сохранённого шаблона мастера + суммы + номера + QR-кода
4. Клиент получает сертификат **только как скачивание PDF-файла** (без отправки на email/SMS)

**Настройка номиналов (в личном кабинете мастера, раздел «Сертификаты» → «Настройки»):**
- Мастер вводит доступные номиналы через запятую, например: `1000, 2000, 3000, 5000`
- Ограничения: каждое значение от 500 до 50 000 ₽, максимум 6 значений в списке
- Валидация на фронте и бэкенде при сохранении настроек
- Клиент при покупке видит только эти номиналы как варианты выбора (без возможности ввести произвольную сумму)

**Настройка срока действия (там же, в настройках):**
- Чек-бокс «Без срока действия» — **включён по умолчанию**
- Альтернатива — указание конкретной даты окончания действия (date picker)
- При выборе даты чек-бокс «Без срока действия» автоматически снимается (взаимоисключающие поля)
- Срок действия — общая настройка на уровне мастера (применяется ко всем сертификатам, выпущенным после изменения настройки); уже выпущенные сертификаты сохраняют условия, действовавшие на момент выпуска

### 2.3. Погашение сертификата у мастера

1. Клиент показывает сертификат (в телефоне или распечатанный)
2. Мастер в личном кабинете открывает «Сканировать сертификат», разрешает доступ к камере
3. Наводит камеру на QR-код
4. Система считывает URL из QR, отправляет запрос на бэкенд для проверки
5. Бэкенд сверяет токен (хэш) с БД, проверяет статус и срок действия
6. **Результат показывается модальным окном:**
   - Успех: номинал, остаток баланса (если уже частично использован), дата покупки, срок действия — с полем ввода суммы списания и кнопкой «Списать»
   - Ошибка: причина — «остаток исчерпан» (с датой последнего списания), «истёк срок действия», «сертификат не найден»
7. Мастер вводит сумму списания (не может превышать остаток), подтверждает → `remaining_amount` в БД уменьшается на введённую сумму, `status` меняется на `used` только когда остаток достигает нуля; при частичном списании статус остаётся `active`, но с обновлённым остатком
8. Каждое списание логируется отдельной записью (для истории операций и на случай спора с клиентом)

## 3. Техническая архитектура

### 3.1. Генерация шаблона (Claude API)

- Вызывается один раз при настройке/изменении дизайна мастером
- На входе: логотип (base64 или URL), основной/дополнительный цвет (HEX), название студии, слоган, контакты
- На выходе: HTML/SVG-разметка сертификата формата A5 landscape с плейсхолдерами:
  - `{{amount}}` — сумма
  - `{{certNumber}}` — номер сертификата
  - `{{issueDate}}` — дата выдачи
  - `{{expiryDate}}` — срок действия
  - `{{qrCodeSvg}}` — QR-код (вставляется отдельно, не через Claude)
- Промпт должен явно фиксировать формат A5 landscape (210×148 мм / пропорции 35:24), чтобы модель не возвращала произвольные пропорции
- Сгенерированный шаблон валидируется на сервере (проверка наличия обязательных плейсхолдеров) перед сохранением

### 3.2. Рендер финального сертификата (без ИИ)

- Технология: **Satori** (HTML/JSX → SVG → PNG) или **Puppeteer/Playwright** (HTML → PDF/PNG)
- Подстановка данных в сохранённый шаблон — обычная строковая замена/шаблонизатор
- QR-код генерируется отдельной библиотекой (`qrcode` для Node.js) и встраивается в шаблон как SVG или base64-изображение перед рендером
- Рендер должен строго держать формат A5 landscape вне зависимости от длины текста (название студии, слоган) — при необходимости уменьшать шрифт, но не менять пропорции холста

### 3.3. QR-код и проверка подлинности

**Кодируемые данные:**
```
https://okno.business/verify/{certificate_uuid}?t={random_token}
```

**Хранение:**
- `random_token` генерируется как криптографически случайная строка (например, `crypto.randomBytes(32).toString('hex')`)
- В БД хранится **только хэш токена** (SHA-256 или аналог), не сам токен в открытом виде
- Сумма и данные мастера НЕ кодируются в QR напрямую — только идентификатор + токен, всё остальное подтягивается из БД при проверке

**Проверка (эндпоинт `/api/certificates/verify`):**
1. Принимает `certificate_uuid` и `token`
2. Хэширует токен, сравнивает с `token_hash` в БД
3. Проверяет `status = 'active'` и `expires_at > now()`
4. Возвращает данные сертификата (сумма/остаток, дата покупки, статус) либо код ошибки

**Погашение / частичное списание (эндпоинт `/api/certificates/redeem`):**
- Отдельный запрос, вызывается только по явному действию мастера («Списать N ₽»), не автоматически при скане
- Принимает `certificate_uuid`, `token`, `write_off_amount`
- Проверяет, что `write_off_amount <= remaining_amount`
- Уменьшает `remaining_amount` на указанную сумму
- Если `remaining_amount` становится равным 0 → `status = 'used'`, фиксируется `redeemed_at`
- Если остаток больше 0 → `status` остаётся `'active'`
- Каждая операция списания пишется в отдельную таблицу истории (`certificate_redemptions`) для аудита

### 3.4. Структура БД (черновой вариант)

```sql
certificate_templates (
  id UUID PRIMARY KEY,
  master_id UUID REFERENCES masters(id),
  html_source TEXT,           -- сгенерированный шаблон
  primary_color TEXT,
  secondary_color TEXT,
  logo_url TEXT,
  created_at TIMESTAMP,
  updated_at TIMESTAMP
)

certificates (
  id UUID PRIMARY KEY,
  master_id UUID REFERENCES masters(id),
  template_id UUID REFERENCES certificate_templates(id),
  cert_number TEXT UNIQUE,    -- человекочитаемый номер, напр. OKN-2026-001000
  amount DECIMAL,             -- номинал на момент покупки (из списка мастера)
  remaining_amount DECIMAL,   -- остаток; уменьшается при частичных списаниях
  token_hash TEXT,
  status ENUM('active', 'used', 'expired', 'cancelled'),
  buyer_contact TEXT,
  created_at TIMESTAMP,
  redeemed_at TIMESTAMP,      -- проставляется, когда remaining_amount = 0
  expires_at TIMESTAMP        -- NULL, если у мастера включено «без срока действия»
)

certificate_redemptions (    -- история частичных списаний, для аудита
  id UUID PRIMARY KEY,
  certificate_id UUID REFERENCES certificates(id),
  amount_written_off DECIMAL,
  balance_after DECIMAL,
  redeemed_at TIMESTAMP,
  redeemed_by_master_id UUID REFERENCES masters(id)
)

master_certificate_settings (
  master_id UUID PRIMARY KEY REFERENCES masters(id),
  available_amounts DECIMAL[],   -- напр. [1000, 2000, 3000, 5000], до 6 значений, каждое 500–50000
  no_expiry BOOLEAN DEFAULT true,
  expiry_date DATE,               -- NULL, если no_expiry = true; при заполнении no_expiry автоматически false
  template_regeneration_count INT DEFAULT 0  -- лимит 3, дальше блокировка перегенерации
)
```

## 4. Требования к дизайну шаблона (для промпта Claude API)

- Строгий формат: **A5, альбомная ориентация**, пропорции 35:24, без отклонений
- Достаточные отступы от края (минимум 10 мм / ~40px при 96 DPI) для безопасной зоны печати
- Логотип не должен искажаться по пропорциям при вставке в шаблон
- Крупный, читаемый номинал суммы — доминирующий элемент композиции
- Место для QR-кода фиксированного размера (минимум 20×20 мм для надёжного сканирования с расстояния)
- Текст должен адаптироваться под разную длину названия студии/слогана без поломки вёрстки
- Шаблон должен корректно рендериться и в PNG (экран), и в PDF (печать) без потери качества

## 5. Решённые вопросы

| # | Вопрос | Решение |
|---|---|---|
| 1 | Частичное списание | Да — реализовано через `remaining_amount` + таблицу `certificate_redemptions` |
| 2 | Номиналы | Только фиксированные, задаются мастером через запятую в настройках. Диапазон 500–50 000 ₽, максимум 6 значений в списке |
| 3 | Срок действия | Настраивается мастером: чек-бокс «без срока действия» (по умолчанию включён) либо произвольная дата — поля взаимоисключающие |
| 4 | Доставка клиенту | Только скачивание PDF-файла, без email/SMS-доставки |
| 5 | Лимит перегенерации шаблона | Максимум 3 раза на аккаунт мастера (жёсткий потолок) |
| 6 | Ручное редактирование шаблона после ИИ-генерации | Не предусмотрено — только перегенерация через Claude API |
