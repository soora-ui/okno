## 5. YooKassa OAuth для мастеров

- [ ] Кнопка «Подключить ЮKassa» в настройках → редирект на `yookassa.ru/oauth/v2/authorize`
- [ ] `state` в OAuth-запросе — непрозрачный ID мастера, не палит внутренние данные
- [ ] Callback обменивает `code` на `access_token` и подтягивает `account_id` через `/v3/me`
- [ ] Токен в БД хранится зашифрованным (`access_token_encrypted`) — подтвердить, что plaintext нигде не логируется
- [ ] После подключения статус меняется на «Подключено ✅» с `account_id` и способами оплаты
- [ ] Тестовый магазин (`is_test_shop=true`) — клиенту либо скрыта оплата, либо явное предупреждение мастеру
- [ ] Кнопка «Отключить» — вызывает revoke, статус переходит в `revoked`
- [ ] Оплата предоплаты клиентом реально уходит в магазин мастера, а не платформы (проверить по тестовому платежу)
- [ ] Истёкший токен (`token_expires_at`) обрабатывается как revoked, мастер получает уведомление подключить заново
- [ ] Возврат платежа идёт через токен того же мастера, не общий аккаунт платформы
