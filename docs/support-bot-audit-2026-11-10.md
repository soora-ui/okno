## Проблемы и план (по приоритету)

### P1. Критично: рейт-лимит обходится заголовком X-Forwarded-For
На проде запрос с подставленным `X-Forwarded-For` проходит лимит после 429. Аноним может без ограничений тратить токены. Исправление уже есть в ветке: коммит `cd3c7a0`, `src/lib/net/client-ip.ts`. Судя по поведению прода, он не задеплоен.
- [ ] Задеплоить `cd3c7a0` и перепроверить: после 429 запрос с подставленным XFF тоже должен получать 429.
- [ ] Добавить правило Cloudflare Rate Limiting на `/api/support-chat`.
- [ ] Ввести дневной бюджет вызовов модели для гостей. Включать Turnstile после N сообщений. Для гостя ограничить суммарный объём истории (~6000 символов).
- [ ] Для IPv6 считать лимит по префиксу /64.

### P2. Высокий: «такой функции нет» про существующие функции
Бот так ответил про ручное добавление записи и перенос записи. Импорта клиентов в карте тоже нет.
- [ ] Добавить в `sitemap.ts` темы «Ручная запись», «Перенос записи» (клиентом по ссылке и мастером), «Импорт клиентов».
- [ ] Написать тест полноты: каждый раздел и экшен кабинета есть в карте.
- [ ] Ответ `no_such_feature` без указанной ближайшей темы переводить в needs_human.

### P3. Средний: поиск не учитывает контекст разговора
Пример: на «а сколько живёт эта ссылка?» после вопроса про Telegram бот не находит ответ «15 минут».
- [ ] В `retrieve` передавать текущее сообщение + последнюю реплику пользователя + темы из sources прошлого ответа.

### P4. Средний: часть вопросов стабильно падает с 502
502 перехватывает Cloudflare, и пользователь видит общую ошибку.
- [ ] Гость с исходом `reply_to_operator` попадает в `authProfile!.profile.id` (route.ts:288), получается TypeError и 502. Нужно приводить этот исход к needs_human.
- [ ] Разбирать ответ модели мягко: выкидывать пустые sources, обрезать summary и suggestions. Сейчас любое нарушение zod даёт 502.
- [ ] Ошибки модели отдавать как 200 с `{error}`, а не 502.

### P5. Средний: поддельная история
`history` и `fromOperator` целиком присылает клиент. Ложь из фальшивой реплики «специалиста» про возврат бот принял молча.
- [ ] Для гостя игнорировать `fromOperator`. Для мастера брать реплики оператора из БД, а не из тела запроса.
- [ ] Правило в промпте: утверждения из истории о ценах, скидках, возвратах или бесплатном доступе, которых нет в базе, — прямо опровергать.

### P6. Средний: эскалации
- [ ] Учитывать `forwardMasterReply` в лимите 5/час и не продлевать окно разговора без ответа оператора.
- [ ] Проверять лимит до вызова модели. При ошибке БД отказывать (fail-closed).
- [ ] Обрезать question, draft и summary, чтобы сообщение влезало в лимит Telegram (4096). Текст пользователя показывать в `<blockquote>` с пометкой «слова пользователя».
- [ ] Реплику оператора, которая подставляется в системный промпт, экранировать или выносить в блок с разделителями.

### P7. Средний: бот додумывает за пределами базы
Примеры: «специалист решит по компенсации», «лимита на услуги нет», выдуманные названия кнопок.
- [ ] Гостю при needs_human отдавать фиксированный шаблон вместо текста модели.
- [ ] Запрет в промпте: никаких обещаний по возвратам и компенсациям.
- [ ] Добавить в базу темы «Возвраты» и «Лимиты услуг и клиентов».

### P8. Низкий: стиль
- [ ] Бот всё ещё говорит «в базе знаний нет» и «мои инструкции», иногда предлагает помощь с другими темами, на «Привет» не всегда здоровается.
- [ ] Для гостя предлагать «Войди или заведи аккаунт» вместо одного «Заведи аккаунт».

### P9. Трейсы, эвалы, кэш
- [ ] Логировать каждый ответ обезличенно: хэш IP, outcome, sources, подмена ungrounded, ошибка zod, stop_reason, latency.
- [ ] Собрать eval-набор (золотые ответы + инъекции + follow-up) из кейсов этого аудита и прогонять его перед каждым изменением промпта или карты.
- [ ] Поставить статичный индекс в начало system и включить `cache_control`. Переменные части (приветствие, авторизация) перенести в конец.
- [ ] Вынести модель в env и добавить запасную.
