# ТЗ: Навигация вкладки «Запись» — сайдбар на десктопе, аккордеон на мобильном

## 1. Проблема

Вкладка «Запись» содержит много разделов подряд: параметры записи, витрина, страницы записи, цветовые палитры, подарочные сертификаты, телеграм-уведомления. Сейчас всё выстроено вертикальным списком — чтобы понять, что вообще есть в разделе, пользователь должен пролистать всю страницу. Особенно плохо на десктопе, где места достаточно, чтобы показать всё сразу без скролла.

## 2. Решение — два разных паттерна по breakpoint

- **Десктоп (`md:` и выше, ≥768px)**: вертикальный саб-сайдбар слева, справа — контент выбранного раздела
- **Мобильный (<768px)**: аккордеон, все разделы свёрнуты по умолчанию

Переключение через Tailwind `hidden md:flex` / `md:hidden`, без дублирования логики состояния — один источник правды (см. п.5).

## 3. Десктоп: саб-сайдбар

### 3.1 Структура layout

```
┌──────────────────┬────────────────────────────────┐
│ Параметры записи ●│                                │
│ Услуги            │   [Контент выбранного раздела] │
│ Витрина           │                                │
│ Страницы записи   │                                │
│ Сертификаты    ⚠  │                                │
│ Цвет. палитры     │                                │
│ Телеграм       ✓  │                                │
└──────────────────┴────────────────────────────────┘
```

- Ширина сайдбара: фиксированная, ~240–280px
- Активный пункт: выделение фона + акцентная полоса слева (2-3px, цвет бренда)
- Контентная зона справа: скроллится независимо от сайдбара, если контент длинный (сайдбар остаётся sticky/fixed в пределах вкладки)

### 3.2 Порядок разделов — по частоте использования

1. Параметры записи
2. Услуги
3. Витрина
4. Страницы записи
5. Подарочные сертификаты
6. Телеграм-уведомления
7. Цветовые палитры

(частые/операционные — наверх; настроил один раз и забыл — вниз)

### 3.3 Статус-индикаторы в пунктах списка

Рядом с названием раздела — маленький индикатор состояния:

| Индикатор | Значение |
|---|---|
| ✓ (зелёная точка/галочка) | Раздел полностью настроен |
| ⚠ (жёлтый) | Раздел настроен частично / требует внимания (например, сертификаты: номиналы есть, дизайна нет) |
| без индикатора | Раздел не тронут / не требует настройки для базовой работы |

Логика показа индикатора берётся из существующих данных состояния каждого раздела (для сертификатов — уже описано в `okno-tz-certificates-ui-flow.md`: «Не настроено» / «Дизайн не готов» / «Готово» / «Активно»).

## 4. Мобильный: аккордеон

### 4.1 Поведение

- Все разделы свёрнуты по умолчанию при заходе на вкладку
- **Single-open**: открытие одного раздела автоматически закрывает предыдущий открытый (не допускаем состояние, когда развёрнуты 3-4 раздела одновременно — на мобильном это провоцирует бесконечный скролл)
- Анимация разворачивания — Framer Motion, `height: auto` через измерение `scrollHeight` или `AnimatePresence` + `layout`, длительность ~250-300ms, easing `easeInOut`

### 4.2 Заголовок полоски (свёрнутое состояние)

```
[Название раздела]              [статус-бейдж]  [шеврон ▾]
```

Статус-бейдж — тот же набор состояний, что в сайдбаре (✓ / ⚠ / пусто), но текстом, если позволяет ширина, либо только иконкой на узких экранах.

### 4.3 Порядок разделов

Тот же порядок, что на десктопе (см. п.3.2) — не дублировать логику сортировки, вынести в общий конфиг (см. п.5).

## 5. Общая архитектура — один источник правды

Чтобы не дублировать список разделов и их статусы в двух разных компонентах (сайдбар и аккордеон), нужен единый конфиг:

```ts
// config/recordTabSections.ts
export const RECORD_TAB_SECTIONS = [
  { id: 'booking-params', label: 'Параметры записи', component: BookingParamsSection },
  { id: 'services', label: 'Услуги', component: ServicesSection },
  { id: 'showcase', label: 'Витрина', component: ShowcaseSection },
  { id: 'booking-pages', label: 'Страницы записи', component: BookingPagesSection },
  { id: 'certificates', label: 'Подарочные сертификаты', component: CertificatesSection },
  { id: 'telegram', label: 'Телеграм-уведомления', component: TelegramSection },
  { id: 'color-palette', label: 'Цветовые палитры', component: ColorPaletteSection },
] as const;
```

Каждый раздел сам предоставляет функцию/хук `useSectionStatus()`, возвращающую `'complete' | 'warning' | 'none'` — и сайдбар, и аккордеон читают статус из одного места.

Родительский компонент вкладки «Запись» рендерит либо `<DesktopSidebarLayout sections={RECORD_TAB_SECTIONS} />` (при `md:flex`), либо `<MobileAccordion sections={RECORD_TAB_SECTIONS} />` (при `md:hidden`) — общий конфиг, разный layout.

## 7. Отдельная задача: балансировка колонок в кабинете мастера (`/dashboard`)

Не связано с навигацией вкладки «Запись» из разделов 1-6 выше — другая страница, но тот же общий принцип «убрать визуальный дисбаланс из-за неравного распределения контента». Добавлено сюда, чтобы держать все UI-правки в одном файле для передачи в разработку.

### 7.1 Проблема

Текущая разметка кабинета мастера:

```
grid gap-6 xl:grid-cols-[1.2fr_0.8fr]
```

**Левая колонка (1.2fr):**
1. Ряд из 3 карточек-метрик (Записи сегодня / Записи на этой неделе / Выручка за месяц)
2. «Ближайшие записи» (подблоки «Сегодня» + «Предстоящие дни»)
3. «Быстрый доступ к своей странице»

**Правая колонка (0.8fr):**
1. «Остаток тарифа» (баннер с прогресс-баром)
2. «Ручная запись» (форма: клиент, телефон, услуга, дата, время, город мастера, комментарий)
3. «Погасить сертификат» (кнопка сканирования QR)
4. «Быстрые действия» (список карточек-подсказок, количество зависит от того, что ещё не настроено у мастера)

Несмотря на то что правая колонка **уже** (0.8fr против 1.2fr), в ней на один блок больше (4 против 3), и один из блоков — полноценная форма из 7 полей. В сумме правая колонка ощутимо выше левой, особенно в пустом состоянии (мало записей → «Ближайшие записи» схлопывается до пары строк-плейсхолдеров, а форма и список остаются полными). Из-за этого короткая колонка заканчивается раньше, рядом продолжается высокая — визуально читается как пустота сбоку.

### 7.2 Решение — не masonry, а перебалансировка состава колонок

Masonry-переукладка тут не подходит: блоки функционально разные (форма, метрики, список, баннер) — их нельзя просто тасовать по алгоритму балансировки высоты колонок, как одинаковые карточки, не сломав логику страницы (например, форма ручной записи должна оставаться цельным блоком, а не разбиваться на части).

**Перенести блок «Быстрые действия» из правой колонки в левую**, разместив его последним, после «Быстрый доступ к своей странице».

Новое распределение:

**Левая колонка:**
1. Ряд из 3 карточек-метрик
2. «Ближайшие записи»
3. «Быстрый доступ к своей странице»
4. «Быстрые действия» *(перенесено)*

**Правая колонка:**
1. «Остаток тарифа»
2. «Ручная запись»
3. «Погасить сертификат»

Это сближает суммарную высоту колонок гораздо сильнее текущего распределения.

### 7.3 Оговорка

«Ближайшие записи» — блок с переменной высотой (зависит от количества реальных записей в конкретный день/неделю), поэтому идеальный баланс 1-в-1 каждый день не гарантирован никаким статичным распределением блоков — в дни с большим количеством записей левая колонка снова станет заметно длиннее правой, и это нормально: полная симметрия тут возможна только через JS-измерение высоты в рантайме (полноценный masonry-реflow), что для данного случая избыточно по трудозатратам относительно выгоды.

### 7.4 Промпт для Claude Code (кабинет мастера)

```

Текущая структура (grid gap-6 xl:grid-cols-[1.2fr_0.8fr]):
- Левая колонка: ряд из 3 карточек-метрик → «Ближайшие записи» → «Быстрый доступ к своей странице»

```
